# Графика и эффекты CosmicFly

Все визуальные ресурсы подключаются через конфигурацию. Игровая логика работает с идентификаторами эффектов и скинов, не с путями файлов.

## 1. Принцип

Есть три слоя:

1. **Логика.** Корабль выстрелил, враг погиб, щит сел.
2. **Идентификатор.** `muzzle-flash-pulse`, `explosion-small`, `trail-engine-a`.
3. **Ресурс.** ключ текстуры, частицы, звук, shake.

EffectsManager и SkinManager — единственные места, которые знают, как идентификатор превратить в картинку.

Запрещено:

- писать `'assets/ships/player.png'` внутри Player, Enemy или GameScene;
- создавать новый набор частиц в каждом враге;
- привязывать боевые статы к имени скина.

## 2. Каталог визуальных систем

### 2.1. Скины кораблей

Первая версия: 3 скина одного корпуса.

| ID | Назначение | Отличие |
| --- | --- | --- |
| `skin-ember` | стартовый | янтарное ядро, короткий тёплый след |
| `skin-ion` | холодный | бирюзовое ядро, более длинный холодный след |
| `skin-void` | контрастный | белое ядро, тёмный корпус, резкая вспышка носа |

Скин меняет:

- текстуру или tint;
- идентификатор следа;
- идентификатор вспышки выстрела;
- лёгкий цвет HUD-акцента.

Скин не меняет:

- скорость;
- урон;
- здоровье;
- размер коллайдера, если это не явно согласованный визуальный масштаб без геймплейного эффекта.

### 2.2. Корабли врагов

Каждый тип врага имеет `visualKey` в данных:

- Sting Dart — узкий осколок;
- Longspire — пика;
- Burst Mite — круглое ядро;
- будущие типы — собственные силуэты.

Враги не переиспользуют скин игрока. Цветовая слепота недопустима: форма важнее оттенка.

### 2.3. Метеориты

Ash Chunk — тёмный спрайт с трещиной. Вращение постоянное, без ИИ. При уничтожении — `explosion-small` и несколько камней-частиц.

Раскол на мелкие метеориты — не раньше этапа 2.

### 2.4. Лазеры и снаряды

`pulse-beam` первой версии — короткий болт, не бесконечный хитскан.

Конфиг снаряда ссылается на:

- спрайт или простую геометрическую текстуру;
- цвет;
- масштаб;
- эффект попадания;
- эффект смерти снаряда.

Позже лазеры могут стать непрерывной полосой, но это отдельный тип оружия, не перекраска болта.

### 2.5. Ракеты

Появляются не раньше этапа 5. Нужны:

- спрайт с носом;
- дымный след;
- отдельный взрыв крупнее пули.

След ракеты не должен использовать тот же emitter, что след игрока, иначе смешаются смыслы.

### 2.6. Взрывы

Три уровня, даже если в v1 используется один:

- `explosion-small` — смерть мелкого врага и пули;
- `explosion-medium` — Burst Mite, метеорит, смерть элиты;
- `explosion-large` — босс, фазовый слом.

Взрыв — это набор: вспышка, кольцо, искры, опциональный shake.

### 2.7. Частицы

Частицы создаются из пула. Нельзя на каждый выстрел делать новый ParticleEmitterManager с нуля, если Phaser позволяет переиспользовать.

Первая версия держит не больше 3 активных профилей:

1. искры попадания;
2. след двигателя;
3. мелкий взрыв.

### 2.8. Следы двигателя

След читает скорость. Чем выше скорость, тем длиннее жизнь частицы, но не бесконечно.

Синергия Dart Rhythm может слегка осветлять след, пока бонус активен. Это визуальный флаг, не отдельный скин.

### 2.9. Щиты

Щит — обод вокруг корпуса, не отдельный корабль.

Состояния:

- полный: яркий тонкий обод;
- повреждённый: рваный обод;
- сломан: короткая вспышка и исчезновение;
- восстановление: обод набирается по кругу.

В этапе 1 щит можно не показывать, если слот ещё не включён в бой. Конфиг всё равно резервируется.

### 2.10. Вспышки

Вспышка носа при выстреле короткая: 80–120 мс. Если она живёт дольше, стрельба выглядит липкой.

Критическое попадание использует более яркий вариант того же эффекта, не новую физику.

### 2.11. Экранный shake

Разрешён только для:

- урона по игроку;
- смерти босса;
- крупного взрыва.

Запрещён для каждого мелкого убийства. Иначе укачивает и прячет снаряды.

Параметры shake живут в `effects.ts`: интенсивность, длительность, оси.

### 2.12. Параллакс-фон

Два-три слоя:

1. далёкая пыль туманности;
2. редкие крупные пятна;
3. ближние мелкие искры.

Слои двигаются от скорости камеры или от вектора игрока с малым коэффициентом. Камера первой версии может быть фиксированной; тогда параллакс берёт вектор движения игрока.

Не делать полноценный тайловый мир.

### 2.13. Энергетические волны

Используются как телеграф, не как украшение:

- импульс Burst Mite;
- фазовый слом босса;
- будущий Strobe Burst игрока.

Волна должна быть кольцом с понятным краем, не заливкой всего экрана.

### 2.14. Эффекты попаданий

Попадание по врагу, по игроку и по метеору — разные идентификаторы. Игрок должен кожей чувствовать, кто получил удар.

Попадание по щиту не выглядит как попадание по корпусу.

## 3. Первая версия: 3 эффекта

Чтобы не раздувать прототип, в контент v1 входят только:

1. `muzzle-flash-pulse` — вспышка выстрела;
2. `hit-spark` — искры попадания;
3. `explosion-small` — смерть врага и метеорита.

След двигателя желателен, но если он требует отдельной настройки частиц, его можно добавить заданием этапа 4. Для каркаса достаточно трёх эффектов из списка пользователя.

Рекомендация Командора: след двигателя включить в этап 4, не в первое задание Штурмана.

## 4. Конфиг эффекта

Логическая форма `EffectDef`:

- `id`
- `kind`: sprite, particles, flash, shake, ring
- `assetKey`
- `durationMs`
- `scale`
- `tint`
- `followTarget`: none, player, muzzle, world
- `shakeRef` опционально
- `audioRef` опционально

Логическая форма `SkinDef`:

- `id`
- `shipTextureKey`
- `engineTrailEffectId`
- `muzzleEffectId`
- `accentColor`

## 5. Источники ассетов

Командор ещё не подключает файлы к проекту. Перед первым графическим заданием нужно:

1. выбрать единый набор, предпочтительно Kenney Space Shooter Remastered или Space Shooter Redux;
2. проверить лицензию CC0 или эквивалент;
3. записать автора, источник, лицензию и дату в `public/assets/attribution/assets.md` и `docs/assets.md`;
4. не смешивать несовместимые стили;
5. крупные файлы вести через Git LFS.

Нельзя использовать:

- ассеты Nova Drift и presskit;
- паки без лицензии;
- «похожие» спрайты с коммерческих витрин без проверки.

Пока набор не выбран и не записан, Штурман может собирать прототип на цветных геометрических текстурах Phaser. Это допустимо для этапа 1.

## 6. Производительность

- пул снарядов и частиц;
- лимит одновременных взрывов;
- не создавать текстуру каждый кадр;
- не включать bloom через тяжёлые пайплайны в первой версии;
- проверять FPS на Canvas fallback, не только на WebGL.

Если частиц больше, чем читаемости, эффект считается ошибочным даже при высоком FPS.
